Apache-licensed HTTP client for a licensed EzClassify REST runtime. It contains generated wire models and client ergonomics, not the proprietary engine or enterprise content. The wire layer is generated by [oapi-codegen](https://github.com/oapi-codegen/oapi-codegen) from [`spec/openapi.yaml`](spec/openapi.yaml).

The [ezclassify/contracts](https://github.com/ezclassify/contracts) repository owns
document and wire types; EzClassify Runtime owns
marking and access evaluation. This client owns HTTP transport, response decoding, caching, and
language-native conveniences. Evaluation operations address a published Context;
health and Context discovery use the deployment endpoint.

## Supported runtimes

Go 1.26.10 or newer. Import the module directly in your application.

## Install

```sh
go get github.com/ezclassify/client-go
```

Then import it under the module-root path:

```go
import "github.com/ezclassify/client-go"
```

Go 1.26.10+.

## Quickstart

Start with the Cedar Valley replay server. It answers over real HTTP with recorded responses for a fictional school-district Context, so you can see your client work before you have a runtime. Node.js 22 or newer is needed for the replay server only.

```sh
npx @ezclassify/conformance-server --scenario cedar-valley --port 4010
```

In your Go module, connect the normal client to it, process a marking, and check access:

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/ezclassify/client-go"
)

func main() {
	ctx := context.Background()
	cx := ezclassify.Connect("http://127.0.0.1:4010", "cedar-valley", "1.0.0")

	res, err := cx.Scheme.Process(ctx, ezclassify.CtxSchemeProcessRequest{Input: "INTERNAL"})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(res.Result.Rendered, res.Result.Valid)

	marking := "CONFIDENTIAL"
	dec, err := cx.Access.Check(ctx, ezclassify.CtxAccessCheckRequest{
		Marking:        &marking,
		UserAttributes: map[string]interface{}{},
	})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("granted:", dec.Result.Granted)
	for _, rule := range dec.Result.Rules {
		if rule.Reason != nil {
			fmt.Println(rule.Rule.RuleID, rule.Granted, *rule.Reason)
		}
	}
}
```

```text
INTERNAL true
granted: false
protection-clearance false The reader’s trusted clearance is below this protection level.
recipient-organization false The reader’s trusted recipient organization is not permitted.
```

The context is `cedar-valley` at version `1.0.0`. The server replays recordings, so it answers a finite set of requests: markings such as `PUBLIC`, `INTERNAL`, and `CONFIDENTIAL`, plus the guide, aggregate, and access cases listed in the [scenario catalog](https://github.com/ezclassify/contracts/tree/main/packages/conformance-server/scenarios/cedar-valley). Any other request gets a 501 diagnostic that names the nearest recording. By default it asks for no credentials. Start it with `--auth simulated` to test sending a bearer token (`ezclassify-conformance-test-bearer`).

### Swap to your runtime

When the integration works, point the same code at your runtime. Change the base URL, supply the credentials your administrator issued, and bind your own Context. The calls stay the same.

```go
client := ezclassify.New(
	"https://runtime.example.com",
	ezclassify.WithCredentials(ezclassify.RestClientCredentials{
		AccessToken:  "caller-access-token",
		ContextToken: "signed-context-token",
	}),
)
cx := ezclassify.ConnectWith(client, "your-context-id", "")
```

The empty version lets the server choose: your Context token's default version, or the newest published when there is no token. Use markings your Context accepts, since the replay server's inputs belong to Cedar Valley. The next section walks a fuller call sequence against a runtime.

## Against a runtime

Obtain the endpoint and credential from your EzClassify runtime administrator, then connect, validate a marking, and run an access check. `Connect` binds a published Context composed by the licensed backend.

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/ezclassify/client-go"
)

func main() {
	ctx := context.Background()

	client := ezclassify.New(
		"http://localhost:3000",
		ezclassify.WithCredentials(ezclassify.RestClientCredentials{
			AccessToken:  "caller-access-token",
			ContextToken: "signed-context-token",
		}),
	)
	ping, err := client.Ping(ctx)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("server:", ping.EngineVersion)

	cx := ezclassify.ConnectWith(client, "cedar-valley-protection", "")

	input := "confidential"
	res, err := cx.Scheme.Validate(ctx, ezclassify.CtxSchemeValidateRequest{Input: &input})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(res.Result.Rendered, res.Result.Valid)

	marking := "CONFIDENTIAL"
	dec, err := cx.Access.Check(ctx, ezclassify.CtxAccessCheckRequest{
		Marking:        &marking,
		UserAttributes: map[string]interface{}{"clearance": "INTERNAL"},
	})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(dec.Result.Granted)
	fmt.Println("resolved:", cx.ResolvedVersion())
}
```

Example output (the server version depends on your deployment):

```text
server: 1.0.1
CONFIDENTIAL true
false
resolved: 1.0.0
```

The lowercase input matched an alias and came back corrected to the canonical rendering. `Connect(baseURL, contextID, version)` constructs its own client; `ConnectWith` reuses one. Omit the version, by passing `""`, to let the server choose: the Context token's default version, or the newest published. `"latest"` means the same. The concrete version each call resolved to is on `ResolvedVersion()`, read from the `X-EzClassify-Resolved-Version` response header. The operation groups are `cx.Scheme`, `cx.Guide`, `cx.Access`, `cx.Document`, and `cx.Crosswalk`, and an `EzClassifyContext` is safe for concurrent use.

The Context facade caches repeated calls; see [Caching](#caching). `cx.Describe(ctx)` returns the Context's description for an audit trail: its scheme, guides, access policy and crosswalks, each with the version it declares beside the concrete version that answered.

```go
description, err := cx.Describe(ctx)
if err != nil {
	log.Fatal(err)
}
fmt.Println(description.ID, description.Version, description.Scheme.ResolvedVersion)
if description.Crosswalks != nil {
	for _, crosswalk := range *description.Crosswalks {
		fmt.Println(crosswalk.ID, crosswalk.Version, "->", crosswalk.ResolvedVersion)
	}
}
```

Optional fields in generated request structs are pointers, hence `&input` and `&marking` above. Wrap a literal with a one-line helper (`func ptr[T any](v T) *T { return &v }`) when it gets noisy.

## Caching

A repeated identical call to the same Context handle does not go over the wire twice. The cache belongs to the handle (`cx`), holds up to 500 results, and is keyed by operation, Context binding and the whole request body. Every field of the request is part of the key, so two `Process` calls that name different `Outputs` or `SuggestFor` are two entries, and `Explain` never answers from a `Process` entry for the same request. A field left nil and a field never set are the same request.

These calls are cached: `Scheme.ApplyPreset`, `Process`, `Validate`, `Explain`, `Suggest`, `SuggestForCategories`, `Aggregate`, `Scan`, `Render`, `Normalize`, `DescribeConcept`, `Diff`, and `Access.Rules`. Everything else reaches the server on every call: the guide operations, `CheckCoverage`, `FilterConcepts`, `Notices`, the scheme views and resources (`Summary`, `Concepts`, `Categories`, `Formats`, `Grammar`, `Scopes`, `LabelPresets`), `Describe`, and the composed document, access and crosswalk operations (`Document.Audit`, `Document.AssessAccess`, `Access.DescribeRequirements`, `Crosswalk.Translate`). The generated `Ctx*WithResponse` methods are direct wire methods and never use the cache. The same behavior holds in every EzClassify client; the [cache contract](https://github.com/ezclassify/contracts/blob/main/libs/conformance/cache/v1/CACHE-SEMANTICS.md) states it, and every client runs the same executable plans against it.

Concurrent identical calls share one request. Canceling one caller's `context.Context` ends that caller's call and leaves the others on the shared request alone; the request itself is canceled when its last caller has gone. A caller that arrives already canceled gets `context.Canceled` without touching the cache.

Failures are never cached. A non-2xx response, a transport error and a malformed success are all returned to the caller and the next call asks the server again. A 200 whose body cannot be decoded, or lacks a member the contract requires at any depth, is a malformed success: the call returns a `*MalformedResponseError`, naming the first missing member when one is missing, rather than a zero-filled result. The same check covers `Ping`, `ListContexts` and `ListContextVersions`, and null where the contract does not allow it counts as missing.

```go
var malformed *ezclassify.MalformedResponseError
if errors.As(err, &malformed) {
	fmt.Println(malformed.Op, malformed.Member) // scheme.process /result/valid
}
```

Every call returns its own result. A `*T` you receive is yours to change, whether it came from the wire, from the cache, or from a request you joined, and nothing you do to it reaches another caller or a later read.

Lifetime depends on the binding. A concrete Context version never changes once published, so its entries are kept until the 500-entry limit evicts them. An unpinned binding, an empty version or `latest`, can move to a newer version, so its entries expire: after five minutes, two for `Scan`, and one hour for `DescribeConcept` and `Access.Rules`.

The cache clears itself when an unpinned binding's resolved version changes, and when the server answers a request with HTTP 401 or with its constant denial-shaped 404 (`{"error":"not_found"}`), since the credential behind the client is no longer the caller the entries were computed for. A 404 that names a missing resource leaves the cache alone. Call `cx.ClearCache()` to drop every entry yourself, or build the client with `ezclassify.WithResponseCacheDisabled()` to always call the server. Use one client for one caller identity, and build a new client when the caller changes, including when HTTP middleware supplies user credentials from request context values.

### Access decisions

`Access.Check` calls the server every time by default. The request is what puts the decision in the deployment's audit record, against the exact artifact versions that answered it, and a decision served from client memory never made that trip. If you choose to trade those audit records for fewer requests on a concrete Context version, build the client with `ezclassify.WithCacheAccessDecisions()`:

```go
client := ezclassify.New(baseURL, ezclassify.WithCacheAccessDecisions())
cx := ezclassify.ConnectWith(client, "cedar-valley", "1.0.0") // a concrete version
```

`ConnectWith` panics when the option is combined with `"latest"` or an empty version, because the composition behind an unpinned binding can move under a cached decision. The option reaches `Access.Check` and nothing else: document audit and assessment, access requirements and crosswalk translation stay on the wire.

## Reading a marking and writing one

Two calls read a marking, and which one you want depends on who is asking.

`cx.Scheme.Validate` is the reader's call. Code that displays a marking, gates on it, stores it, or hands its facts to an access check calls it, with the marking as text in `Input` or as stated facts in `Assertions`, never both:

```go
text := "confidential"
read, err := cx.Scheme.Validate(ctx, ezclassify.CtxSchemeValidateRequest{Input: &text})
if err != nil {
	log.Fatal(err)
}
if !read.Result.Valid {
	for _, e := range read.Result.Errors {
		fmt.Println(e.Message)
	}
}
```

`Valid` says whether the marking stands once the server has settled it. `InputWasValid` says whether it was right as written, and when it was not, `AppliedFixes` and `Errors` say why. Pass facts only as a document or an author stated them: the `Assertions` of an earlier result are already settled, and validating those can call a marking valid whose text was not. An error about a token the server could not read may carry `DidYouMean`, the ids of the concepts it may have been meant as. `Message` gives the same hint in words for people; `DidYouMean` is for code, and it is not a fix.

`cx.Scheme.Process` is the author's call. It answers everything `Validate` does, settled the same way, plus what someone writing the marking needs: the corrections to the text in `Recognition.Corrections`, the fix paths the server has proven in `ProposedFixes`, a render for each output named in `Outputs`, and picker options for each category named in `SuggestFor`. A composer sends what was typed together with the facts already picked:

```go
draft, err := cx.Scheme.Process(ctx, ezclassify.CtxSchemeProcessRequest{
	Input:      typed,
	Assertions: &pickedSoFar,
	Outputs:    &[]string{"short"},
	SuggestFor: &[]string{"level"},
})
if err != nil {
	log.Fatal(err)
}
preview(draft.Result.Renders["short"].Rendered)
if draft.Result.SuggestionsFor != nil {
	offer((*draft.Result.SuggestionsFor)["level"].Suggestions)
}
```

`Renders` holds only the outputs you name, and `SuggestionsFor` is nil unless you name categories. `cx.Scheme.SuggestForCategories` answers the same map on its own, keyed by category id, when there is nothing to process. `cx.Scheme.Explain` takes what `Process` takes apart from `Outputs` and `SuggestFor`, and returns the trace instead: what was read, repaired, inferred, and found wrong, and what was written.

Outputs are spelled the way the scheme declares them: a format id, or for a scheme that declares surfaces, a `surface/view` address such as `sensitivity/short`. When a request names no `OutputFormat`, a scheme without surfaces writes its default format, and a scheme with surfaces writes each surface in its default for the marking's role. That role is the request's `Context` role when it gives one, otherwise the role recognition reports in `Recognition.Role`, and a marking with neither is written as a whole. `Recognition.InputFormat` reports what the text was read as: the view's address for a scheme that declares surfaces, the format id otherwise. `cx.Scheme.Summary` reports `DefaultWholeRenderFormat` and `DefaultPartRenderFormat`, and each entry `cx.Scheme.Formats` returns lists in `DefaultFor` the roles it is the default for.

What a render could not write is listed in `Assessment.Unrepresentable`, on the result and on each entry of `Renders`. An entry is either one fact the format has no way to write or, for a scheme that declares surfaces, a whole output that was refused. Both `As` methods decode any entry without an error, so tell them apart by `Output`, which only a refused output carries:

```go
for _, entry := range res.Result.Assessment.Unrepresentable {
	if refused, err := entry.AsUnrepresentableOutput(); err == nil && refused.Output != "" {
		fmt.Println("refused", refused.Output, refused.Reason)
		continue
	}
	fact, err := entry.AsUnrepresentableFact()
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("cannot write", fact.ConceptID, fact.Reason)
}
```

The `From` and `Merge` methods on an entry build values and have no use on a response.

## Picker inputs

`cx.Scheme.Suggest` takes text in `Input` or stated facts in `Assertions`,
exactly one of the two. Both fields are pointers: nil means absent, while a
pointer to an empty string or slice is valid input. `InputFormat` only applies
to text, on both Suggest and Validate. The remaining declared fields are
forwarded unchanged, including `IncludeGated: ptr(false)`.

Assertion `Source` is an open string. Custom labels, values, metadata and
provenance pass through the SDK. Core processing recognizes `infer`, `default`,
`context`, and `repair` with `SourceRule` as previously derived facts; other
labels such as `parse`, `user` and `stated` remain authored input. Settling
and derivation belong to the server.

A `DescribeConcept` refusal classified as `concept_not_found` is an `APIError`
with the original status and payload, not a `ContextNotFoundError`. Missing
Context and credential refusals retain the binding error contract.

## Scheme views and presets

`cx.Scheme.Categories`, `Concepts`, and `Formats` return the views a local engine's scheme view carries: `CategoryView`, `ConceptView`, and `FormatView`, which holds a format's resolved layout and its syntax. `cx.Scheme.LabelPresets` returns `LabelPresetView` entries for the Context's primary scheme, the scheme `ApplyPreset` expands them in, so it takes no scheme selector. `ApplyPreset` takes the preset id and the `OutputFormat` to write the expanded marking in, and answers what `Validate` answers:

```go
presets, err := cx.Scheme.LabelPresets(ctx)
if err != nil {
	log.Fatal(err)
}
if len(*presets) > 0 {
	expanded, err := cx.Scheme.ApplyPreset(ctx, ezclassify.ApplyPresetRequest{PresetID: (*presets)[0].ID})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(expanded.Result.Rendered)
}
```

`Scopes` returns the declared scopes in declaration order, an empty slice when the scheme declares none.

## Errors and rate limits

Every non-2xx response is an `*APIError` carrying the operation, the status, the raw body, and the decoded error body when it has one. A 404 that names a missing Context is a `*ContextNotFoundError` wrapping it. A 2xx that breaks the response contract is a `*MalformedResponseError` (see [Caching](#caching)). A request the client refuses before sending it, such as a validate or suggest request with both or neither of `Input` and `Assertions`, or scan or audit text that is not valid UTF-8, is an `*InvalidInputError` whose `Detail` says why without echoing the value.

The server refuses a request that names a query parameter or body field its operation does not declare, with a 400 whose `code` is `INVALID_INPUT` and whose `detail` names it. The request types in this package carry only declared fields, and the SDK adds no others.

The rate limiter answers ahead of every route, so any operation can return a 429. `APIError.RetryAfter` is the wait the server asks for, read from the `Retry-After` header and, if that is absent, from the body. It is zero on any other status. The client never sleeps or retries on its own. When you wait, bound the wait yourself, since the value comes from the server:

```go
var apiErr *ezclassify.APIError
if errors.As(err, &apiErr) && apiErr.StatusCode == http.StatusTooManyRequests {
	wait := min(apiErr.RetryAfter, 30*time.Second)
	select {
	case <-time.After(wait):
		// send the request again
	case <-ctx.Done():
		return ctx.Err()
	}
}
```

## Notices

A validate, process, preset, or aggregate result carries the notices the scheme attaches to the concepts in the marking, on `Result.Notices`, and so does the `Result` of every scan match. The field is always sent and is empty when the marking carries none, so a loop over it needs no presence check:

```go
for _, n := range res.Result.Notices {
	fmt.Println(n.ConceptName, n.Text, n.Required)
}
```

`cx.Scheme.Notices(ctx, req)` collects the same list for assertions you built somewhere else. For a marking this SDK just processed, read the field instead of making the second call.

## Context discovery and generated surface

Use `client.ListContexts(ctx)` and `client.ListContextVersions(ctx, id)` to discover bindings before calling `ConnectWith`. The embedded generated client also exposes canonical `Ctx*WithResponse` methods for callers that need response headers or typed error bodies directly. `cx.Describe(ctx)` returns a Context's component breakdown: its scheme, layers, guides, access policy, and crosswalks, each with the version it declares and the concrete version that answered; `client.CtxDescribeWithResponse` is the same request with the raw response.

```go
contexts, err := client.ListContexts(ctx)
if err != nil {
	log.Fatal(err)
}
if len(contexts.Contexts) == 0 {
	log.Fatal("no Contexts are available to this caller")
}
cx := ezclassify.ConnectWith(client, contexts.Contexts[0], "")
input := "confidential"
result, err := cx.Scheme.Validate(ctx, ezclassify.CtxSchemeValidateRequest{Input: &input})
if err != nil {
	log.Fatal(err)
}
fmt.Println(result.Result.Rendered, result.Result.Valid)
```

Operations with no REST endpoint (registry mutation, in-process scheme loading, event subscriptions) are out of scope for an HTTP SDK.

## Authentication

Use `RestClientCredentials` for the two independent credentials. `AccessToken` is sent as a bearer token on every REST request. `ContextToken` is sent as `x-ezclassify-context-token` only on `/v1/ctx` routes, so it cannot leak to health or other route families:

```go
client := ezclassify.New(baseURL, ezclassify.WithCredentials(ezclassify.RestClientCredentials{
	AccessToken:  accessToken,
	ContextToken: contextToken,
}))
```

The zero-value credential struct is valid for an unauthenticated local runtime. Blank non-empty tokens are rejected. Use `WithHTTPClient` when you also need a custom transport, retry policy, cookie jar, or redirect policy:

```go
type headerTransport struct {
	base    http.RoundTripper
	headers map[string]string
}

func (t *headerTransport) RoundTrip(r *http.Request) (*http.Response, error) {
	r = r.Clone(r.Context())
	for k, v := range t.headers {
		r.Header.Set(k, v)
	}
	return t.base.RoundTrip(r)
}

httpClient := &http.Client{
	Transport: &headerTransport{
		base:    http.DefaultTransport,
		headers: map[string]string{"X-Org-Id": "acme"},
	},
}
client := ezclassify.New(
	"http://localhost:3000",
	ezclassify.WithHTTPClient(httpClient),
	ezclassify.WithCredentials(ezclassify.RestClientCredentials{AccessToken: accessToken, ContextToken: contextToken}),
)
```

`ConnectWith(client, ...)` carries the same transport and credentials into context-bound calls. The supplied `*http.Client` is shallow-copied and is never mutated.

### Timeouts

Every call finishes within the client's timeout, 30 seconds unless you set another. The bound covers the whole request: connecting, waiting for the answer, reading the full body, the redirects the client follows, and any retry your transport makes, which share what is left of it rather than starting over. It holds when you pass `context.Background()`, when the client given to `WithHTTPClient` has no `Timeout`, and when a transport you supply ignores the request context, since the SDK stops waiting on it at the deadline. A call that runs out of time returns an error matching `errors.Is(err, context.DeadlineExceeded)`.

`WithTimeout` sets the bound and must be positive; it panics on zero or less. It overrides the `Timeout` of a client given to `WithHTTPClient`, and a supplied client without one gets the 30 second default. A `context.Context` deadline shorter than the client's wins, so pass one for a single call that must answer sooner. Cancelling the context ends the call with an error matching `errors.Is(err, context.Canceled)`.

```go
client := ezclassify.New(baseURL, ezclassify.WithTimeout(10*time.Second))
```

### Response size

`New` takes its settings as options. `WithMaxResponseBytes` sets the response ceiling: a client reads at most `ezclassify.DefaultMaxResponseBytes` (32 MiB) from a single response body and fails a longer one with an error wrapping `ezclassify.ErrResponseTooLarge`, rather than truncating it.

```go
client := ezclassify.New(baseURL, ezclassify.WithMaxResponseBytes(128<<20))
```

The limit must be positive: `WithMaxResponseBytes` panics on zero or less, so no caller code can remove the ceiling. It applies to every operation, generated or handwritten, because it sits on the transport.

## Versioning

SDK `major.minor` tracks the rest-api `major.minor`; patch versions may drift. `client.EngineSpecVersion()` is the spec version this SDK was compiled against, `client.Ping(ctx)` returns the live server version, and the first mismatch logs a warning via `log.Printf`.

## Examples

Three runnable commands live under [`examples/`](examples/). Start the replay
server from the [quickstart](#quickstart), then run either of these from the
repository root:

```sh
go run ./examples/basic
go run ./examples/server-tour
```

[`basic`](examples/basic/README.md) validates a marking, aggregates two, and
checks access. [`server-tour`](examples/server-tour/README.md) lists the
Contexts a server publishes and processes a marking. Both default to
`http://127.0.0.1:4010`, Context `cedar-valley`, version `1.0.0`, and their
READMEs show the output. To switch to your runtime, pass `--server`, `--ctx` and
`--ctx-version`, set `EZC_ACCESS_TOKEN` and `EZC_CONTEXT_TOKEN` if your runtime
requires them, and use markings your Context accepts.

[`go-classify`](examples/go-classify/README.md) scans a directory of files for
markings. It sends arbitrary file text, which the replay server has no
recording for, so it needs a runtime that serves the Context; its README has
the setup. `go build ./...` covers all three.

## Integration testing

The quickstart server doubles as an integration test fixture for your backend. Use your normal client to test connectivity, response handling, and access-decision logging. Supported requests are listed in the
[replay server guide](https://github.com/ezclassify/contracts/tree/main/packages/conformance-server#testing-an-application-integration).
Unrecorded requests return a diagnostic rather than computing a new answer.

The quickstart prints each rule's explanation without copying subject
attributes or credentials into the output. In your backend, derive attributes
from trusted identity data and add your application's correlation ID and
resource reference. Apply your log retention and redaction policy to returned
explanations too. A denied access decision is a successful response with
`granted: false`; handle transport or authentication failures separately.

Restart with `--scenario transient-error`, `rate-limit`, `unavailable`,
`slow-response`, `disconnected`, `malformed-json`, or `malformed-envelope` to
exercise failures on the recorded process request. Clear the client response
cache or create a new client between runs so an earlier answer does not hide
the scenario. The guide lists authentication, validation, empty-result, and
complex access cases. These recordings test your integration, not the
correctness of a production authorization policy.
